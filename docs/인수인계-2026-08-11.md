## 3. 분류기 현황 (2026-08-11 개정)

개정 전 문제는 **감사 로그 5회 연속 반영 0건**이었다. 원인은 범위 판정이 아니라 근거 등급
게이트였고, 게이트를 열자 단계 규칙의 오분류가 드러났다.

### 측정치 (2026-08-11 배치 306건)

| 지표 | 개정 전 | 개정 후 |
| --- | --- | --- |
| 직영 판정 | 50건 (16.3%) | **173건 (56.5%)** |
| 검토 대기 | 242건 (79.1%) | 119건 (38.9%) |
| 하청 격리 | 12건 | **12건 (유지)** |
| 주 단계 변경 가능 | 3건 | 20건 |

하청 격리가 그대로인 것이 중요하다. 포함 범위를 넓히면서 배제 정밀도를 잃지 않았다.
직영 판정 173건 중 하청 어휘가 남은 기사는 0건이다.

```bash
node scripts/measure-classification.mjs
```

네트워크 없이 저장된 후보를 다시 분류해 깔때기를 출력한다. **규칙을 손대기 전후에 같은
입력으로 돌려 비교한다.**

### 고친 오분류 (회귀 테스트로 고정)

- **조합원 가결이 최종 체결(S7)로** 올라갔다. 가결·인준은 S6, S7은 서명·조인·발효다.
- **파업 찬반투표가 인준 투표(S6)로** 읽혔다. 파업으로 가는 상황이 타결 직전으로 표시됐다.
- **단계 하강 방어가 없었다.** 파업 기사가 교착(S4)을 본교섭(S3)으로 내릴 수 있었다.

### 범위 판정 규칙

- **배제는 어휘 신호**(`하청·사내협력사·용역·파견·계열사`)로 한다. 정밀도가 높아 손대지 않는다.
- **포함은 두 등급**이다. 정식 교섭단위명은 `CONFIGURED_UNION_ALIAS`, 법인명 근처 20자 안의
  `노조·노동조합·지부·노사` 표현은 `COMPANY_UNION_PHRASE_NO_EXCLUSION_SIGNAL`이다.
- 혼재는 **강한 근거와 배제 신호가 함께** 있을 때만 쓴다.
- 레지스트리에 하청 교섭단위를 추가하면 약한 경로는 그 법인에서 자동으로 꺼진다.

## 6. 미완료 작업

우선순위 순이다.

1. **Worker 시크릿 등록** — `SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`·`DASHBOARD_ADMIN_CODE`를
   `npx wrangler secret put`으로 넣어야 **기록 수정 요청 기능이 동작**한다. 지금은 `503`이다.
   `kkj.env`는 로컬 파일이고 배포된 Worker는 자기 시크릿을 본다.
2. **대시보드의 DB 읽기 전환** — 화면이 정적 JSON을 읽는다. DB에 같은 사실이 있으므로
   두 곳에 중복 상태다. 전환 시 정적 시드와 DB의 정정 이력 우선순위를 정해야 한다.
3. **익명 역할 검증** — `anon` 키가 없어 "공개 행만 보이는지"를 실제로 확인하지 못했다.
   RLS 정책은 마이그레이션에 있으나 실환경 검증이 남았다.
4. **과거 경과 조사 41건** — 3절·2절 참고. 법인·연도별로 근거 URL을 확인해
   `data/historical-flow-events.json`에 넣으면 빌더가 검증 후 병합한다.
5. **DART 교차검증** — `OPENDART_API_KEY`가 이미 있다. 상장사의 파업·조업중단은 주요경영사항
   공시 대상이라 `S4` 판정의 독립 근거가 된다. 지금은 기사 제목 하나에 의존한다.
6. **NAVER 검색 API 전환** — `data/source-config.json`이 유료 경로(API HUB)를 가리킨다.
   무료 한도(하루 25,000회)가 있는 것은 NAVER Developers 오픈 API이며, 수집기는 이미
   `legacy` 인증을 지원하므로 **config 두 줄 수정**이면 된다. 키 발급은 사람 작업이다.
7. **원문 URL 되돌리기 예산** — 직영 후보가 늘어 상한이 병목이다. 현재
   `maxUrlResolutions: 150`이고, 더 올리면 실행 시간이 요청당 약 0.3초씩 늘어난다.

## 7. 자격증명 현황

값은 이 문서에 기록하지 않는다. **어디에 무엇이 있는지만** 남긴다.

| 이름 | 보관 위치 | 용도 |
| --- | --- | --- |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | GitHub 시크릿 | 자동 배포 |
| `MAIL_SMTP_USER`, `MAIL_SMTP_PASSWORD` | GitHub 시크릿 | 수집 결과 메일 |
| `SUPABASE_PJT_URL`, `SUPABASE_SERVICE_ROLE_KEY` | 로컬 `kkj.env` | 적재 스크립트 |
| `DASHBOARD_ADMIN_CODE` | 로컬 `kkj.env` | 기록 수정 요청 관문 |
| `OPENDART_API_KEY`, `TAVILY_API_KEY`, `OPENAI_API_KEY` | 로컬 `kkj.env` | 아직 미사용 |
| `NAVER_API_HUB_*` | 없음 | 미발급 |
| Supabase `anon` 키 | 없음 | 익명 역할 검증에 필요 |

주의할 점.

- **`service_role` 키는 RLS를 우회한다.** 서버·로컬에서만 쓰고 브라우저·`NEXT_PUBLIC_`·정적
  파일·로그에 넣지 않는다.
- `kkj.env`는 `KEY = value`(등호 양옆 공백) 형식이다. 셸 `source`로는 읽히지 않고,
  `startsWith("KEY=")` 같은 매칭도 실패한다. 스크립트를 쓸 때 공백을 감안한다.
- 이 프로젝트의 파이프라인은 **LLM을 호출하지 않는다.** 분류·범위 판정·단계 승격은 전부
  규칙 기반 코드다. 외부 호출은 Google News(및 NAVER 키가 있을 때 NAVER)뿐이다.

## 8. 지키고 있는 원칙

바꾸기 전에 이유를 확인해야 하는 것들이다.

- **사실은 제목이나 회사명만으로 추정하지 않는다.** 원문 URL·확인일·직접고용 범위 근거·
  출처 등급을 함께 보존한다.
- **기사 본문을 복제·저장하지 않는다.** 제목·매체·발행일·원문 URL과 계산된 분류만 남긴다.
  메일 본문도 같은 경계를 지킨다.
- **하청·간접고용 사례는 원청 상대 교섭이라도 공개 대시보드에 섞지 않는다.**
- **`S6`을 `S7`로 올리려면 조합원 가결이 아니라 서명·조인·발효 근거가 필요하다.**
- **수정은 접수와 공개를 분리한다.** 사람이 제출한 수정도 `PENDING`으로만 들어가고,
  근거 URL·사유·수정자가 없으면 접수하지 않는다.
- **GitHub schedule은 보장이 아니다.** 하루 세 번 시도하고, 멈추면 감시 워크플로가 실패로
  드러내며, 화면 상단이 마지막 수집일과 지연일수를 표시한다.
- **근거가 없으면 빈 칸으로 둔다.** 값이 없는 항목을 그럴듯하게 채우지 않는다.
